# 修订日志：引用锚定与幻觉率修复

日期：2026-08-08
影响模块：`app/mult_agents/nodes.py`、`app/mult_agents/prompts.py`

## 问题现象

用 `app/eval/judge_metrics.py`（Qwen 严格裁判）对 8 条完成评测（4 条研究类报告）实测：

- 声明级幻觉率：94.6%（37 条研究声明中 35 条判定为 unsupported/contradicted）
- 语义引用准确率：14.7%（34 条引用中仅 5 条能在对应来源找到支撑）
- 典型错误：引用 URL 返回 404、域名非法、时间错位（2026 年页面支撑 2025 年事件）、量化数据在原文中不存在

## 根因

1. WebScout（LLM）整理网页证据时，可以对合法 `source_id` 编造 `url/title/snippet`；原 `_enrich_evidence_from_raw` 只在字段缺失时补全，不会覆盖 LLM 编造的值。
2. EvidenceJudge 在 `evidence_pool` 中同样可能改写 `url/locator`，后续 `source_index` 直接使用这些字段。
3. Writer 虽校验了引用 ID 是否存在于 `source_index`，但未校验正文 Markdown 链接是否为真实来源，也未约束无来源的量化数据。

## 修改方案

1. `_enrich_evidence_from_raw`：改为强制覆盖 `url/domain/title/snippet/source_type/published_at`，证据字段一律以 Bocha/Milvus 原始检索记录为准。
2. `deep_dive_node`：`evidence_pool` 生成后再次锚定原始检索记录，防止裁判改写 URL/标题。
3. 新增 `_strip_unapproved_links`：正文 Markdown 链接必须命中 `source_index.locator` 白名单，否则退化为纯文本。
4. `write` 提示词补充硬约束：无来源的数据/机构/时间一律写“暂无可靠公开来源”或“待核实”，禁止编造数字与 URL。

## 验证步骤

1. `docker compose --env-file .env.docker up -d --build backend`
2. 重跑 `app/eval/run_eval.py`（10 条示例集）
3. 重跑 `app/eval/judge_metrics.py`，对比修复前后幻觉率/引用准确率

## 结果

### 修复前（2026-08-08，8 条完成，4 条研究类）

- 声明级幻觉率：94.6%（研究声明 37 条中 35 条）
- 语义引用准确率：14.7%（34 条中 5 条）
- 完备性：45.0

### 修复后（2026-08-08，9 条完成，5 条研究类；q08 因 DashScope 读超时失败）

- 声明级幻觉率：84.2%（全量 57 条中 48 条；研究声明 48 条中 39 条，即 81.3%）
- 语义引用准确率：19.2%（52 条中 10 条）
- 完备性：47.2
- 重点案例 q06（LangGraph vs CrewAI）：幻觉率 28.6%、引用准确率 62.5%

### 结论

- 引用锚定修复有效：`_enrich_evidence_from_raw` 强制覆盖后，source_index 中的 URL/标题不再由 LLM 编造；正文 Markdown 链接也做了白名单校验。
- 当检索证据与问题相关时（q06），引用准确率显著提升。
- 整体指标仍不理想，剩余根因：Bocha 返回的源多为低质中文站点、snippet 无量化数据；q07 出现 2026 年页面支撑 2025 年事件的时效错位；Writer 仍会把证据缺口用模型记忆补全。
- 下一步：加入信源质量/时效过滤、只允许引用 snippet 可证内容、对无证据细节强制写“暂无可靠公开来源”。
